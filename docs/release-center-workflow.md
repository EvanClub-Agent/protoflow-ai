# 版本中心维护流程

版本号以 `DesktopRelease.version` 为准。页面主标题由该字段生成；`title` 仅作为选填主题。旧表单曾预填 `0.2.0` 标题，修改版本号不会同步修改标题，因此历史记录可能出现冲突。新页面向管理员显示明确诊断，公开下载页不展示冲突标题；不会自动改写数据库里的旧记录。

1. 新建版本，填写版本号和真实更新说明，保存为草稿。
2. 选择平台并上传安装包。至少一个平台的安装包完成签名确认后即可发布。
3. 发布后仍在同一版本内补充其他平台或架构的安装包，原有平台继续提供下载。
4. 版本信息、撤回、删除操作放在版本详情中；安装包操作绑定详情的版本 ID 和资产 ID。

未提供的平台显示“暂未提供”，不代表整个版本不可用。安装说明和文件摘要默认收起。上传期间锁定编辑及关闭操作；失败保留选择，允许重试。遵循 Alex / ProtoFlow 文件命名规则的安装包会检查文件名版本与所选版本是否一致，这不是对包内部元数据的验证。

## 验证

- `npm test`：版本标题、分平台状态、切换版本后补包的精确归属。
- `npm run build`、`npm run build:viewer`。
- `node scripts/release-center-smoke.cjs`：在隔离的本地 HTTP 页面和模拟 API 下，通过真实 Chromium 操作创建草稿、仅发布 Linux、补充 macOS、上传失败重试、公开下载和移动端布局。不会连接或修改生产服务。
- 设置 `PFLOW_RELEASE_UI_SCREENSHOTS=/tmp/protoflow-release-ui-preview` 可保存冒烟测试截图。
