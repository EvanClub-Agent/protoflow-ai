# 运行诊断

这是桌面应用的统一异常采集通道。诊断不能把一次失败解释为模型能力问题；它保留可核对的运行标识和结构证据，供进一步定位。

## 已接入的场景

| 来源 | 采集点 |
| --- | --- |
| AI | 项目工作流、页面任务、会话执行失败、上下文连接异常 |
| 工具 | 每轮失败工具数量和工具名称，包含 MCP 与原生工具 |
| 渲染 | window.error、未处理 Promise 拒绝、React 错误边界、自由组件失败、渲染进程异常退出 |
| 存储 | 自动保存失败，以及打开、保存、导出等桌面 IPC 失败 |
| 网络 | 发布、更新等桌面 IPC 失败和更新器错误状态 |
| 主进程 | 其他桌面 IPC 失败、uncaughtExceptionMonitor；保留原有异常退出语义 |

正常取消不会作为失败上报。不是全量 console 或 fetch 录制；新业务中被主动捕获并消化的错误，需要通过 `captureRuntimeError` / `captureDiagnostic` 接入。纯浏览器演示端没有桌面采集桥，当前不会自动上传访客错误。不包含系统级原生崩溃 dump。

## 反馈和查询

1. 桌面工具栏点击“运行诊断”（虫形图标），查看本地记录、上传状态、复制编号或导出脱敏 JSON。React 出错界面也有该入口。
2. 项目 AI 失败回复附带“复制诊断编号”。编号表示本地记录成功；是否已入库以诊断窗口的状态为准。
3. 平台管理员登录 `/releases/admin` 后，打开“查询运行诊断”，按完整编号、版本、来源、完整用户名/账号 ID、设备名/安装实例 ID 或 runId 查询。每页最多 50 条，展开查看账号、电脑、根因证据、分阶段耗时及完整 JSON；“查看此电脑同一任务的全部诊断”可关联渲染进程、主进程和工具错误。

开源构建与发行安装包默认**仅在本地保存诊断记录，不自动上传**（Opt-in）。用户若连接了自建服务并希望向团队管理员共享诊断，可在诊断窗口手动开启上传；服务地址使用固定发行源或当前已连接的自建发布服务地址，绝不从模型输出或渲染进程参数推导。

## 数据与边界

- PostgreSQL 表：`diagnostic_installations`、`runtime_diagnostics`，迁移 `008_runtime_diagnostics.sql`。
- 每次安装生成独立 UUID 和随机写入凭证（本机文件权限 0600，服务端只存哈希）；该凭证只能登记、上传，不能读取诊断或使用发布/管理接口。上传入口仍属于客户端报告入口，不代表用户账号认证。
- 报告编号为 UUID，每次重试保持原编号。服务端只接受同安装、同编号、同内容的幂等重试；冲突不能覆盖原报告。
- 读取接口复用平台管理员身份验证和现有管理网络限制。普通发布凭证、客户端用户及安装凭证不能查询。
- 每条请求最多 64 KiB；服务端验证类型、字段、枚举、时间和上下文白名单。沿用现有 IP 限流。
- 本地 JSON outbox 最多 200 条、7 天；相同上下文的相同错误 30 秒内复用编号。上传失败指数退避（30 秒至 1 小时）；永久格式拒收会单独标记，不阻塞后续报告。超过本地保留上限会清理，并展示本次启动后的未上传清理数量。
- 数据库默认保留 90 天，服务启动后及每 24 小时按服务端接收时间清理；同时清理超过 90 天且没有报告的安装登记。
- 默认只采集错误摘要、脱敏栈、版本/平台/架构、真实项目/页面/会话/轮次 ID 和白名单结构信息。凭证格式、URL、用户主目录在客户端和服务端均做脱敏。不采集提示词、思考文本、完整 AI 回复、页面源码、图片、表数据行和完整项目快照。
- AI 验收报告记录候选页的依赖状态、原始表/外键 ID、动作锚点和实际 `table` 绑定。场景需求原文不上传，必要时仍需用户另行提供最小复现资料。无法构造合法候选页时，仅保留阶段与已有运行标识。
- 捕获、落盘或上传失败不会改写原业务异常或放宽验收规则。网络上传不在生成或保存的等待链上；异常首次产生时做小体积本地持久化。

## 接口

- `POST /api/v1/diagnostics/installations`：`{id,token}`，同凭证重试允许；不同凭证不能接管已有安装。
- `POST /api/v1/diagnostics/reports`：Bearer 安装凭证、`X-Diagnostic-Installation` 安装 UUID；结构化报告正文，返回 `{id,stored:true}`。
- `GET /api/v1/admin/diagnostics?id=&category=&version=&account=&device=&runId=&offset=0`：Bearer 平台管理员凭证，返回 `{items:[...]}`。所有筛选精确匹配；客户端不能指定任意数据库字段或排序 SQL。

新增采集点示例：

```ts
void captureRuntimeError(error, {
  category: 'storage',
  code: 'PROJECT_SAVE_FAILED',
  stage: 'autosave',
  context: { projectId },
});
```

含用户原文的 AI 错误应提供固定 `message`，将有用证据放入明确白名单上下文。不得展开整个业务对象、工具参数或接口请求头。

## 账号、设备和 Hermes 根因证据

- `account` 是错误发生时的账号快照，由主进程从已校验的登录或 `/auth/me` 响应提取 `userId`、`username`、`displayName`。不会用 publisherId、操作系统用户或安装编号代替账号。启动尚未确认身份为 `unknown`，退出/认证失效后为 `signed-out`。离线日志在捕获时冻结身份，切换账号和重启后的上传不会改变它；渲染进程传入的账号和设备字段被忽略。
- `account.source=client-session` 明确表示客户端报告的登录会话快照，不是服务端对报告内容的认证证明，不能用于鉴权或计费。旧记录无账号字段时明确显示未采集，不按当前登录状态补写历史。
- `device` 从操作系统读取 `hostname`、`osRelease`、`osVersion`，与现有 platform、arch、installationId 一起定位电脑；不采集硬件序列号、MAC 地址、密码或会话令牌。重装可能更换 installationId，设备名也可以修改，两者均不是永久硬件身份。
- 通用 ACP `session/prompt -32603` 失败时，只读取当前 Hermes home 下 `errors.log` 和 `agent.log` 各最多 512 KiB 尾部，匹配精确 sessionId、本轮起止时间和固定日志格式。只有明确的 `API call failed after … retries` 终止事件才可作为根因证据，单独的已恢复警告不会被当作最终原因。未匹配或不可读取会显式记录 `logStatus`，不猜测其他会话的故障。
- `context.failure` 仅允许已知分类、证据来源、时间和数字：限流类型、最后一次拒绝建议等待秒数、Token 限额/已用/请求量、尝试次数、重试是否耗尽、消息数与估计 Token 数。Hermes 估计量和服务报告的请求量保持不同字段；原始错误、日志正文、模型回复、组织 ID 和服务 URL 不上传。日志格式变更或时间漂移可能无法匹配，仍保留原 ACP 错误码。
- `context.metrics` 记录总耗时、会话准备、首输出、Hermes 等待、工具调用数量/耗时和输入字节数等数字白名单。它不包含提示词、工具参数或完整快照。
- 已修正客户端和服务端脱敏正则的单词边界，防止将 `task-suspend` 误识别为 `sk-` 密钥而丢失检查名称。
- 扩展字段存于现有 JSONB，不增加数据库迁移。必须先升级后端，再发布桌面包，否则旧后端会拒收未知字段。此改动不调整模型额度、上下文压缩策略或 Hermes 重试策略，也不会自动重放可能含写入操作的任务。

### 请求恢复诊断（后端已部署，客户端待更新）

本次另行实现的限流恢复见 [AI 限流恢复与上下文完整性](ai-rate-limit-recovery.md)。它直接读取单次 provider 响应进行重试，历史日志仅用于诊断，不驱动自动重放。

- 本地 `request-recovery/<逻辑会话摘要>.json.status` 与 `.json.events` 记录精确 sessionId/runId、等待/重试/恢复/停止状态、次数、服务建议等待及实际等待；事件文件限 256KiB 后轮转。不含提供商原始错误体、提示词或密钥。
- 主进程 `context.metrics.providerRetryCount`、`providerWaitMs` 记录该轮实际重试与等待；等待属于 `acpTurnMs` 的子项，不能再与总耗时相加。服务端白名单已同步。
- `context.checks` 的 `provider-retry` 说明停止原因，`draft-recovery` 区分 saved、uncertain、unavailable。正常取消不上报故障；本地仍保留等待和草稿状态。
- Responses 的结构化服务拒绝由 `provider-response` 记录允许的错误码与 `responses-error-event` 来源；`provider-exception` 记录固定白名单中的异常类型。不上传错误正文，不将 SSE 错误假定成 HTTP 429。已知限流/额度等分类和数值继续写入 `context.failure`，无需新数据库迁移。因旧草稿状态不确定而被拦截时，保留 `draft-recovery=uncertain` 并分类为 `stale-state`。
- 候选快照、原始请求和待提交操作只保存在本地会话恢复文件，不发送到诊断数据库。账户和设备快照继续沿用上述采集边界。
